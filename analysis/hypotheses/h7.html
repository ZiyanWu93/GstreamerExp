H7 — With the encoder starved, the queue-delay-target knob starts trading picture quality

refutedGoal 2.2 (knob sensitivity), follow-up to H6

Claim

H6 found the queue-delay-target knob moves latency but not picture quality, because the encoder had bytes to spare. With the bitrate ceiling dropped from 4000 to 800 kbps, the encoder is hungry, so loosening the knob should now raise picture quality (PSNR) as well as latency.

Findings and Limitations

Findings

  • Starving the encoder did not turn the knob into a quality knob. With the ceiling dropped to 800 kbps, picture quality (PSNR) still stays flat as the knob loosens — about a 1 dB swing on each network, the same flat pattern H6 saw at 4000 kbps. So the queue-delay-target is a latency knob, not a quality knob, at both ceilings for this workload.
  • The robust takeaway across H6 and H7 is one finding, now tested twice -- the knob moves latency, not quality.

Limitations

  • Measurement caveat — read before trusting the absolute numbers: the PSNR values in H6 and H7 sit at 10–13 dB on every single cell. That is far below what a working pipeline should produce (a heavily compressed VP8 stream is normally 28–40 dB). A value near 10 dB is the signature of comparing misaligned frames — decoded frame N against source frame M not equal to N, or a resolution / colour-plane mismatch in the decoded_psnr truth pipeline.
  • What this caveat does and does not undermine. The relative finding (quality does not move with the knob) holds, because every cell uses the same metric and the comparison is internal. Any absolute quality claim is suspect until the metric is checked against a known-good baseline.
  • Next verification step is a one-cell sanity check — clean loopback, no impairment, near-lossless encode. If PSNR there is also ~10 dB the metric is misaligned and needs fixing; if it is ~40 dB the metric is sound and the stressed-network numbers are genuine.
  • Same workload and clock-skew caveats as H6.
